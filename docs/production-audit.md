# Аудит ConceptLoom Desktop

Начало аудита: 21 октября 2026; финальная проверка: 22 октября 2026. Исходная версия: `c7fd6a5`, ветка исправлений `codex/production-audit`, Desktop 0.3.1.

## Продукт и границы проверки

Приложение для самостоятельного обучения по собственным материалам: пространство → PDF/текст → направление → карта зависимостей → занятие → проверка ответа → карточки FSRS. Репетитор использует Ollama или официальный клиент аккаунта. React/TypeScript отвечает за интерфейс и правила обучения; Tauri/Rust — за SQLite, локальный поиск и запуск клиентов. Отдельный Node MCP сохраняет исходный сценарий обучения внутри coding-клиента.

Прочитаны авторские исходники desktop и MCP, миграции, конфигурация, сценарии установки, тесты, адаптеры, документация EN/RU и три таблицы стилей. Сгенерированные зависимости, бинарные PDF/иконки и сборочные каталоги не считаются проверенным исходным кодом. Lock-файлы проверяются установщиком/аудитом зависимостей. SVG используются как изображения, не исполняемый HTML. База пользователя не изменяется; проверки используют временные базы и браузерные фикстуры.

Предположения: основной продукт — Windows desktop с минимальным окном 1000×700; браузер служит отдельным preview. Офлайн-режим относится к Ollama. Полная мобильная версия не входит в текущий контракт. Подписки и права на модели контролируют сами сервисы.

Хорошо: транзакционные изменения SQLite, составные внешние ключи, ограничение Ollama loopback-адресами, явное согласие для аккаунтов, проверка цитат, отсутствие HTML из модели, реальная FSRS и отсутствие выдуманного прогресса.

## Обязательные исправления

Порядок учитывает влияние и трудоёмкость (S — небольшое, M — несколько связанных модулей, L — отдельная фаза). Критических уязвимостей с подтверждённой эксплуатацией не найдено. Ниже — исходные находки; статус реализации приводится отдельно.

1. **A01 · high · S — Нельзя отозвать согласие.** `desktop/src/features/settings/Settings.tsx`, submit: сохранение аккаунта с `accountDataConsent=false` запрещено. Пользователь не может остановить будущую передачу контекста, сохранив сервис. Разрешить сохранение отключённого согласия; запросы уже блокируются на обеих границах.
2. **A02 · high · S — Неверный JSON конфигурации на Windows.** `scripts/setup.mjs`, `materializeTemplate`: путь с обратными слешами подставляется в JSON как сырой текст. Claude/OpenCode не смогут прочитать конфигурацию. Экранировать строку как JSON и проверить итог парсером; сохранить YAML-экранирование отдельно.
3. **A13 · high · S — Gemini заменяет центральные настройки.** `desktop/src-tauri/src/accounts.rs`, `prepare`: проверка учитывает admin policy, но пропускает системный `settings.json` и пользовательский путь к нему. Подмена системных настроек может отключить ограничения организации. Отказывать при наличии центральных настроек/переопределения, не изменяя их. Дополнительно ограничить stdout/stderr и завершение процесса для проверки входа Codex тем же механизмом, что inference.
3. **A03 · high · M — Потеря конкурентных записей MCP.** `src/progress.mjs`, `saveLearningState`/`recordCheckpointAssessment`: общий временный файл и чтение старого состояния до записи. Воспроизведение: 8 параллельных сохранений → 7 ошибок, revision=1. Сериализовать весь read/modify/write по сессии, использовать уникальный временный файл; проверить накопление evidence.
4. **A04 · high · M — Выход notebook через ссылку.** `src/notebook.mjs`, `ensureInside`: проверяется только лексический путь, существующий junction/symlink может вести наружу. Проверить реальные родительские пути и цель до создания/записи. Тест: junction внутри временного workspace на внешнюю временную папку; внешнее содержимое должно остаться прежним.
5. **A05 · high · S — Ответ прошлого занятия виден в новом.** `App.tsx`/`LessonScreen.tsx`: компонент не имеет ключа темы; поздний `setFeedback` после смены курса попадает в уже другую тему. Разделить экземпляры по теме, сохранив запись результата в исходный курс. Проверить задержанный AI-ответ после смены курса.
6. **A06 · high · M — Занятие может навсегда заблокировать маршрут.** `types/state.ts`/`ai/schemas`: схема допускает только два recognition-задания. Их успешное выполнение не достигает порога 61%, даже с recall-карточками. Проверять наличие всех четырёх измерений на границе новой генерации, не отвергать уже сохранённые старые занятия.
7. **A07 · high · M — Экспоненциальный расчёт карты.** `KnowledgeMap.tsx`, `depth`: общий предок пересчитывается по каждой ветви. Даже допустимый DAG из 30 плотно связанных узлов вызывает огромное число обходов. Вычислять глубины один раз на узел; тест с плотным DAG.
8. **A08 · medium · S — Токен проверки теряется при ошибке.** `src/checkpoints.mjs`/`bridge.mjs`: токен удаляется до проверки входа и успешного сохранения. Ошибка confidence/записи лишает возможности повторить запрос. Потреблять после успешной валидации, а в MCP — после сохранения; сериализовать вызовы bridge.
9. **A09 · medium · M — Диалоги не удерживают фокус.** Формы источников, направлений, карточек, пространств, цитат и карты: большинство не имеют Escape/focus trap/возврата фокуса, часть не объявлена диалогом. Ввести общий доступный контейнер и проверить клавиатуру, вложенные цитаты и ошибки сохранения.
10. **A10 · medium · S — Настройки затирают внешние изменения.** `Settings.tsx`: сохранение целого старого снимка отменяет смену темы в верхней панели. Применять только поля, изменённые пользователем относительно исходной формы, к последнему состоянию.
11. **A11 · medium · S — Светлая тема плохо показывает обратную связь.** `styles.css`: тёмные фоны `.feedback` остаются с тёмным текстом светлой темы; `.capybara small` использует слабый контраст. Исправить токены, проверить обе темы; добавить имена прогресс-барам и доступный импорт файла.
12. **A12 · medium · S — Неверные обещания и ошибка онбординга.** `Home.tsx`: «работает без интернета» показано и для аккаунтов; `Onboarding.tsx`: ошибка сохранения пустого пространства на шаге 3 не выводится. Уточнить текст и показать статус; дать управление окном до завершения онбординга и при ошибке загрузки.

## Оставшиеся риски и предложения

- **B01 · medium · L — Масштаб библиотеки:** `repository.ts`, `changes.ts`, `sourceIndex.ts`, `Statistics.tsx`. Всё состояние загружается целиком, сохранения сериализуют источники, статистика многократно обходит историю. Нужны ленивые страницы/сущности и агрегаты после отдельного нагрузочного профиля. Текущий аудит не утверждает поддержку огромной библиотеки.
- **B02 · medium · M — Аккаунтные клиенты:** `accounts.rs`. Реальный ответ Claude/Gemini требует соответствующего входа; он не проверен. Нужны проверки совместимости при обновлении CLI и пользовательская отмена фоновых процессов. Центральные настройки Gemini теперь защищены A13. Автоматическое обновление до неизвестной версии не выполняется.
- **B03 · medium · M — Native validation:** `changes.rs`. SQLite защищает отношения, но не повторяет все Zod-ограничения payload. Добавить общую версионированную схему IPC перед расширением команд/импорта.
- **B04 · low · M — Локализация:** `main.tsx`, Settings, старые учебные экраны. Часть сообщений и подписей остаётся на английском; единый словарь покрыт предложением F05. Старые milestone-отчёты уже помечены как исторические, README и security policy обновлены.
- **B05 · medium · M — Единый лимит ответа:** `ai/sourceLearning.ts`, `Tutor.tsx`, `types/state.ts`. В mixed-ответе два поля допускают по 12 000 символов, а сохранённое сообщение — 20 000. Очень длинный корректный ответ может не сохраниться. Согласовать общий бюджет с заголовками и лимит обычного chat, показывать возможность получить сокращённый ответ; покрыть границы и повтор без дубля вопроса вместе с F02.

Обновление в 0.3.2: [P1](p1-source-tutor.md) ограничивает оба structured-поля 9000 символами и сохраняет draft/retry без дубля вопроса. Объединённый mixed-ответ укладывается в 20 000; отдельный лимит обычного неструктурированного chat остаётся дальнейшим улучшением.

Не более пяти новых функций, в порядке ценности:

1. **F01 · medium · L — Проверяемый экспорт/восстановление.** Settings + repository: версия формата, проверка перед восстановлением, резервная копия до замены. Защищает накопленный прогресс; полезнее косметики и достижений.
2. **F02 · medium · M — Повтор неудачного запроса репетитору.** Tutor: сохранять состояние запроса и повторять без дубля вопроса. Устраняет потерянное действие при сетевой ошибке; полезнее новых режимов чата.
3. **F03 · medium · L — Отмена генерации/импорта.** AIProvider/native capture/PDF: отменять именно принадлежащую запросу работу. Уменьшает ожидание и лишнее расходование лимита; полезнее добавления ещё одного провайдера.
4. **F04 · medium · M — Управление библиотеками.** Library: переименование и удаление с явным переносом источников. Исправляет ежедневную организацию материалов; полезнее новых форматов без управления существующими.
5. **F05 · medium · L — Полная локализация RU/EN.** Общий словарь и форматирование дат для legacy-экранов. Устраняет смешение языков; полезнее игр/XP на текущей стадии.

Сравнение с категорией проверено по официальным руководствам: [Anki — backups](https://docs.ankiweb.net/manual/backups) и [exporting](https://docs.ankiweb.net/manual/exporting) описывают восстановление и перенос коллекции с расписанием; это поддерживает приоритет F01. [Gemini Notebook — организация источников](https://support.google.com/gemininotebook/answer/16206563?hl=en) описывает независимые notebooks, выбор источников и управление метками, а [chat](https://support.google.com/gemininotebook/answer/16179559?hl=en-CU) — переход к цитатам. В ConceptLoom уже есть изоляция workspace, выбор контекста и цитаты; нехватка управления библиотеками отражена в F04. Остальные предложения — вывод из наблюдаемых сбоев и текущих сценариев, не заявление о наличии функции у конкурента.

## Журнал реализации и проверка

На момент фиксации исходного отчёта: 18 MCP-тестов, 27 desktop unit-тестов, 13 Rust-тестов проходят; 2 Ollama-интеграции и 1 реальный аккаунтный smoke-тест намеренно не запускались. `npm audit` сообщает 0 уязвимостей во всех npm-зависимостях. Это не аудит исходников зависимостей и не проверка Rust advisory database.

Исправлены **все 8 high-находок и 5 medium-находок A01–A13**. Новые зависимости и миграции пользовательской базы не добавлялись.

- **A01/A10:** `Settings.tsx`, `db/settings.ts`: сохранение отключённого согласия и слияние только изменённых полей. Unit-тест проверяет смену темы вне формы и отзыв согласия; E2E проверяет сохранение после перезагрузки.
- **A02:** `scripts/setup.mjs`: JSON-экранирование путей и проверка результата; отсутствие значения `--target` даёт usage с кодом 2. Регрессии запускают реальный installer во временных папках для Claude/OpenCode/DeepSeek.
- **A03/A04/A08:** `progress.mjs`, `notebook.mjs`, `checkpoints.mjs`, `bridge.mjs`: блокировка сессии на весь read/modify/write, уникальный temp + rename, проверка реальных путей, потребление токена после сохранения. Проверены 8 параллельных сохранений и 8 оценок (revision=16, attempts=8), отказ junction вне workspace, повтор после ошибки сохранения и отказ повторного успешного токена. После аварийного завершения процесс может оставить `.json.lock`; закрыть все клиенты и удалить только указанный пустой каталог блокировки перед повтором. Проверка путей не является OS sandbox против локального процесса, одновременно подменяющего ссылки.
- **A05/A06:** `App.tsx`, `LessonScreen.tsx`, `ai/schemas/index.ts`: отдельный экземпляр занятия для темы, строгая схема новой генерации с recognition/recall/application/transfer; старые неполные занятия читаются и могут обновить задания, сохраняя evidence и FSRS. Новые задания получают новые ID. E2E задерживает ответ и переключает курс; второй сценарий восстанавливает legacy-урок с сохранённой попыткой.
- **A07:** `learning/conceptloom/index.ts`, `KnowledgeMap.tsx`: мемоизация глубины после проверки DAG. Плотный граф из 30 узлов проверяется unit-тестом.
- **A09/A11:** новый `components/Dialog.tsx` и формы: native modal, Tab/Shift+Tab, Escape, возврат фокуса, локальный alert ошибки, блокировка прокрутки. Кнопки цитат больше не отправляют внешнюю форму. `capybara.css` исправляет light feedback и вторичный текст; импорт доступен клавиатурой, у progressbar есть имя. `index.html` объявляет основной язык ru. Ошибка storage сохраняет черновик и видна внутри диалога — E2E.
- **A12:** `Home.tsx`, `Onboarding.tsx`, `App.tsx`, `main.tsx`: точное описание account/offline, ошибка шага 3, WindowBar в загрузке/ошибках/онбординге.
- **A13:** `accounts.rs`: отказ при центральном `settings.json`, custom system-settings path или policy Gemini; Codex login status использует ограниченные потоки и завершение дерева процесса. Rust-тест проверяет отсутствие настроек, custom path и наличие центрального файла.

Проверено после исправлений: **25 MCP + 30 TypeScript + 14 Rust = 69 тестов прошли**, ещё **10/10 Playwright** на production frontend. Два opt-in Ollama-теста и один аккаунтный Rust smoke пропущены. Проверены PDF с выделяемым текстом и повреждённый PDF, вставка текста >20 000 символов, изоляция workspace, источник → маршрут → занятие → evidence → FSRS → повторное открытие. CAPYBARA-layout проверен при 1000×700, 1366×768 и 1920×1080; светлый и тёмный скриншоты просмотрены. TypeScript/Vite production build проходит. Единственное предупреждение размера bundle — lazy PDF-reader 540.69 kB; это не стартовый chunk интерфейса.

**Windows NSIS 0.3.1 успешно собран**: `desktop/releases/ConceptLoom_0.3.1_x64-setup.exe`, 5.83 MiB. SHA-256 и коммиты — в локальном `desktop/releases/ConceptLoom_0.3.1-build.json`. Логи: `production-audit-{frontend,rust,e2e,mcp,build}.log` в той же игнорируемой папке. Логи/установщик не включаются в Git. ## Как проверить

Из корня: `npm run verify` — 25 MCP-тестов и syntax checks. Из `desktop`: `npm test` — 30 unit-тестов, 2 opt-in Ollama-теста пропущены; `npm run build` — TypeScript и production frontend. `cargo test --manifest-path src-tauri/Cargo.toml` — 14 Rust-тестов, 1 opt-in реальный аккаунтный тест пропущен.

Для production E2E из `desktop`: `$env:PLAYWRIGHT_PREVIEW = '1'; npx playwright test --workers=1`. Для упаковки: `npm run package` (нужны Cargo/MSVC/Windows SDK в PATH). Тесты используют отдельное preview-хранилище и временные SQLite; установленная пользовательская база не менялась.

Ручные проверки в установленной сборке: вставить текст и импортировать PDF с выделяемым текстом; открыть цитату и вернуться; Tab/Shift+Tab/Escape в диалоге; изменить тему вне открытой формы Settings и сохранить другое поле; отозвать согласие и убедиться, что учебный account-запрос блокируется; переключить курс во время ответа; обновить неполное старое занятие; закрыть и открыть приложение и проверить прогресс. Для каждого реального аккаунта выполнить Sign in → Test response на выбранной модели.

Не проверены в этом аудите: inference под реальными Claude/Gemini-подписками, актуальные права аккаунтов на модели, OCR, полноценная NVDA-проверка, нагрузка больших библиотек, сторонние исходники зависимостей и Rust advisory database. Автоматические браузерные тесты не заменяют нативную проверку WebView2/экранным диктором. Внешние руководства проверены 22 октября 2026; они не устанавливают права на конкретную подписку.
