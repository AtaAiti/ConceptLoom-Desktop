# P5: обзор раздела с честным покрытием

Desktop 0.3.6. Пятый срез [продуктового плана](notebooklm-product-review.md), поверх P1–P4. Затем реализован [P6: сравнение двух понятий с подтверждениями](p6-source-comparison.md) в Desktop 0.3.7; все шесть MVP-срезов завершены.

## Пользовательский путь

1. **Источники → выбранный материал → Обзор раздела**. Открытие, импорт и просмотр сохранённого результата не вызывают ИИ.
2. Выбрать начало/конец и язык. Приложение показывает фактические номера страниц (или части текста), число символов и выбранную модель. Допустимы 1–5 последовательных страниц, до 7 200 Unicode-символов и 6 полных фрагментов. Пустая страница, слишком длинный текст или неверный диапазон блокируют запрос с объяснением. Нет скрытого усечения до первых двух фрагментов.
3. **Создать обзор** выполняет один structured-запрос к текущему провайдеру: только полный выбранный раздел, без других страниц, направлений или переписки. Прежнее согласие для аккаунтного провайдера сохраняется; отдельный провайдер/ключ не добавляется.
4. Результат — ровно 3 тезиса, 3 термина с определениями, 3 вопроса. У каждого есть ссылки на переданные фрагменты. Заголовки источников, номера страниц и выдержки разрешает приложение, а не модель. Неизвестные ссылки или неверная структура результата отклоняются целиком.
5. Обзор сохраняется локально. В шапке результата всегда видны именно разобранные страницы, язык, провайдер/модель и время создания. У источника хранится последний обзор; новый успешно сохранённый результат заменяет предыдущий.
6. Клик вопроса открывает существующий P1-репетитор с редактируемым текстом вопроса и одним точным фрагментом. Это не отправляет вопрос модели автоматически. Направление нужно только для репетитора; сам обзор работает без направления.

## Кэш, актуальность и ошибки

- `source.guide` — необязательное поле; старые источники/резервные копии продолжают работать. Кэш учитывает SHA-256 всех страниц, диапазон, язык, провайдера/модель и версию промпта. После перезапуска восстанавливаются последний диапазон и язык. Совпадающий кэш открывается без inference.
- Хеш включает текст, номера/порядок страниц и section, включая страницы вне выбранного диапазона. Переименование источника или сохранение метаданных обзора не меняют хеш. Проверка консервативна: любое изменение текста помечает старый результат **«Обзор устарел»**, сохраняет его для чтения и блокирует старые вопросы. Новый запрос выполняется только по кнопке.
- Старое покрытие допускается в backup, даже если документ стал короче. Его нельзя выдавать за покрытие нового текста. Ограничения нового запроса проверяются относительно текущих страниц.
- Ошибка модели не меняет импортированный источник и прежний обзор. Ошибка диска оставляет сгенерированный результат в текущем окне; **Сохранить обзор** повторяет только запись. Несохранённый результат можно отбросить.
- Закрытие генерации/выход из источников/смена пространства отбрасывает поздний ответ. Уже отправленный запрос может завершиться у провайдера, но не записывает результат после закрытия. Во время фактической записи закрытие временно недоступно.
- Очередь сохранения повторно проверяет принадлежность и точное содержимое источника. Удалённый источник не восстанавливается. Новые метаданные источника сохраняются; scoped commit остаётся в исходном пространстве.

## Код и границы

- `desktop/src/ai/sourceGuide.ts`: полное ограниченное покрытие без поиска, проверка ссылок, SHA-256, кэш, генерация и чистая функция сохранения в актуальное состояние. Допустимые IDs также перечислены в enum динамической JSON-схемы ответа, чтобы Ollama ограничивал их уже при генерации, а не только после неё. Последнее поручение явно просит перевод на выбранный язык.
- `desktop/src/types/sources.ts`: схемы результата/метаданных/покрытия и optional guide. `db/repository.ts`: запрет переноса обзора между источниками/пространствами при загрузке/импорте.
- `features/library/SourceGuideDialog.tsx` и `Library.tsx`: выбор диапазона, состояния генерации/сохранения/ошибки, чтение результата и цитат, повтор записи, защита позднего ответа.
- `SourceTutorBridge.tsx` и `App.tsx`: необязательный вопрос в существующей передаче точного фрагмента; обычная кнопка P1 сохраняет прежний вопрос.
- SQLite продолжает хранить JSON источника. Новых SQL-таблиц/миграций/зависимостей нет. Изменение только guide не перестраивает source_chunks/FTS. Карточки, интервалы FSRS, сообщения, попытки и mastery не меняются при создании/чтении обзора.

MVP не обобщает целую книгу, не делает map/reduce, OCR, фоновую генерацию или сравнение P6. Наличие корректной ссылки подтверждает переданный фрагмент, но не гарантирует смысловую точность вывода модели; исходный текст доступен для проверки.

## Проверка

Результат: **64 TypeScript unit + 17 native Rust + 39 production-browser E2E passed**; отдельно прошёл **1 live smoke на локальной qwen3:4b** с синтетическими английскими заметками и русским результатом (без пользовательских материалов/платных API). В обычном запуске 4 opt-in Vitest и 1 аккаунтный Rust test пропускаются; из них новый guide smoke выполнен отдельно. Браузерные тесты используют подменённые ответы ИИ. Точность всех смысловых утверждений и всех языков этим не доказывается.

Live smoke обнаружил две проблемы, не видимые на mock-ответах: свободно придуманные citation IDs и игнорирование английского указания языка. Первая исправлена enum в JSON Schema при сохранении финальной проверки ссылок; вторая — явным поручением о переводе и русским финальным запросом. Smoke не смягчён: он проверяет кириллицу в тезисах, все девять элементов, canonical evidence и валидность сохранения.

$env:PLAYWRIGHT_PREVIEW='1'

`test/source-guide.test.ts` проверяет полноту/границы контекста, кэш, хеш, ошибки модели, ownership, backup, точечный/idempotent save, изменение/удаление источника и очереди разных пространств. `e2e/source-guide.spec.ts` проверяет реальную production-сборку с подменёнными ответами ИИ: новый обзор, цитаты/вопрос P1, dark/light, reopen, stale, язык, ошибка записи с retry, отсутствие направления, длинный/нечитаемый текст и отмена позднего ответа. Rust проверяет сохранение/reopen JSON и отсутствие удаления/перестройки текстовых chunks.
