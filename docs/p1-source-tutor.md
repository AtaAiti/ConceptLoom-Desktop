## Что получает пользователь

- Кнопка **«Разобрать с репетитором»** рядом с текущей страницей, в предпросмотре и внутри цитаты.
- Короткий фрагмент открывается в Tutor с направлением и черновиком вопроса; длинная страница предлагает выбор части. Пустой текст не отправляется. Без направления предлагается создать его.
- Видимый фрагмент и правило «только по этому фрагменту»; настройки источников курса не меняются. Генерация начинается только после «Отправить».
- **«Вернуться к источнику»** открывает исходную страницу извлечённого текста.
- Ошибка оставляет вопрос и контекст. После записи вопроса контекст восстанавливается и после перезапуска; «Повторить запрос» использует ту же запись вопроса.
- Удалённый/изменённый источник блокирует отправку с предложением выбрать фрагмент заново. Историческая цитата остаётся снимком и не считается актуальной версией.

## Реализация

- `SourceTutorBridge.tsx` — общий вход из Library, SourceDialogs и Citations, выбор фрагмента/направления, контекст React без новой зависимости.
- `sourceIndex.ts` — глобальные ID чанков при выборе страницы, проверка workspace/source ID/текста/страницы до inference. Это те же page-bounded чанки, что и в индексе.
- `App.tsx`, `draft.ts` — отдельные draft/busy по workspace и course; восстановление неотвеченного вопроса. Поздняя операция обновляет только свой draft ID; навигация не разрешает второй запрос до окончания первого в том же направлении.
- `Tutor.tsx` — явная отправка, сохранение вопроса до inference, retry по message ID, сохранение ответа перед очисткой поля, возврат к чтению. Старые неотвеченные вопросы можно вернуть в поле.
- `sourceLearning.ts` — закреплённый фрагмент передаётся напрямую, без повторного BM25-поиска и без чужих страниц. История ограничена тем же закреплённым фрагментом; прежние ответы/ошибки из другого контекста не подмешиваются. Existing provider/consent/sourcePolicy и проверка citation IDs сохраняются.
- `types/sources.ts`, `types/state.ts`, `repository.ts` — optional `pinnedSource` и `replyTo` в JSON сообщения, проверка границ workspace и связи ответа с вопросом. Новые SQL-таблицы/миграции не нужны; старые сообщения остаются валидными. Два поля mixed-ответа ограничены 9000 символами каждое, чтобы с заголовками помещаться в лимит сообщения 20 000.
- `capybara.css` — ограниченный по высоте, прокручиваемый excerpt и существующие токены светлой/тёмной темы.

Чтение, переход, объяснение и его сохранение не меняют mastery, attempts или FSRS.

## Проверка

- Unit: ID чанка при выборе страницы, вопрос без лексического совпадения, исключение посторонней истории, запрет foreign/deleted/changed context до вызова модели, восстановление вопроса и завершённого ответа, границы сохранения mixed-ответа.
- E2E: страница → ошибка → reload → retry без дублей → цитата → новый handoff → возврат к чтению → другое пространство; длинная страница; изменённый и удалённый источник; отсутствие курса; поздний ответ после перехода к другому фрагменту.
- Реальный локальный smoke с Ollama `qwen3:4b`: вопрос без терминов поиска получил ответ с валидной ссылкой на закреплённый фрагмент. Использован только синтетический учебный текст, не база пользователя.

Команды из `desktop`: `npm test`, `npm run build`, затем `$env:PLAYWRIGHT_PREVIEW='1'; npx playwright test --workers=1`. Opt-in локальный smoke: `$env:OLLAMA_INTEGRATION='1'; npx vitest run test/source-handoff.test.ts -t 'real local model'`. Для обычного тестового запуска переменная должна быть отключена.

Итог: **35 unit-тестов и 16/16 production Playwright-сценариев прошли**, TypeScript/Vite build успешен. В обычном запуске 3 opt-in проверки пропущены; новая проверка pinned-source отдельно запущена с реальным `qwen3:4b` и прошла. Просмотрены скриншоты при тёмном viewport 1366×768 и светлом 1000×700; горизонтального overflow нет. Единственное Vite size warning относится к прежнему lazy PDF-reader.

## Границы первого среза

Это готовый MVP P1 с прежними citation-кнопками, не автоматическая проверка истинности каждого утверждения. Привязка citations к каждому абзацу остаётся улучшением P1; она не блокирует следующий P2. Оригинальный PDF не сохраняется, поэтому возврат открывает извлечённый текст страницы, без координатного выделения в PDF.

Неотправленный черновик хранится в памяти текущего запуска, включая переходы между экранами. После успешной записи вопроса его source snapshot сохраняется в SQLite и восстанавливается при неудачном/прерванном ответе. Пользовательская отмена и новые методы хранения/синхронизации не добавлены. API новых сервисов не подключены; Ollama локальный, аккаунтный CLI требует прежнего согласия и расходует лимит аккаунта.
