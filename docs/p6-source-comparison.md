# P6: сравнение двух понятий с подтверждениями

Desktop 0.3.7. Последний из шести MVP-срезов [продуктового плана](notebooklm-product-review.md), поверх P1–P5.

## Пользовательский путь

1. **Репетитор → Сравнить понятия**. Ввести два разных названия и выбрать источники текущего пространства. Начальный выбор берётся из текущего фрагмента P1 либо источников направления; его можно изменить только для этого сравнения. Из узла карты первое понятие уже заполнено. Без материалов есть переход к обычному импорту PDF/текста.
2. **Сравнить по источникам**: два независимых локальных поиска, по одному для каждого названия. До трёх полных отрывков на сторону, до шести уникальных отрывков по 1 200 Unicode-символов. Общие отрывки передаются один раз. Объединённый запрос по двум названиям и скрытый обзор первых страниц не используются.
3. Результат содержит три критерия с двумя колонками, подтверждения для каждой ячейки и вопрос на применение. Отсутствие подтверждения — явная пустая сторона с текстом «Поиск не нашёл подтверждения в выбранных источниках». Если не найдено ни одного отрывка для обоих названий, тот же честный результат формируется без запроса к ИИ.
4. Правильный результат автоматически записывается в беседу одной парой question/answer. **Сохранить объяснение** добавляет ответ в существующие закладки P2 / Учебный центр. После перезапуска остаются читаемые критерии, обе стороны, ссылки `[N]`, вопрос и исходные цитаты. **Вернуться в беседу** закрывает окно; **Новое сравнение** начинает следующий запрос, сохраняя прежний ответ в истории.
5. Цитаты открывают прежнее окно исходного фрагмента. Переход из него к P1 закрывает окно сравнения и показывает новый черновик с точным фрагментом; сам переход не отправляет вопрос модели.

## Правила доказательств и ограничения

- MVP сравнивает **только источники**, в том числе когда обычный репетитор находится в mixed-режиме. Общие знания, текущая переписка, сведения о других курсах/пространствах модели не передаются. Настройки источников обычного репетитора не меняются.
- Для каждой стороны есть свой набор разрешённых citation IDs. Динамическая JSON Schema ограничивает поддержанную ячейку её набором; отсутствующая ячейка имеет `text:null, citationIds:[]`. При нуле результатов для стороны схема допускает только отсутствие. Нельзя заполнить сторону цитатой, найденной исключительно для другого понятия. Результат повторно валидируется приложением, заголовки/страницы/выдержки разрешаются по canonical chunks.
- Из широких OR-результатов отбираются только отрывки, содержащие все слова запрошенного названия. Это консервативный лексический поиск по существующему индексу, без синонимов, перевода запросов или смыслового поиска. Название в другом языке/падеже может не найти материал. Отсутствие совпадения не означает, что информации нет во всём документе; нужно уточнить формулировку или источники.
- Ссылки подтверждают переданный отрывок, но не доказывают смысловую точность каждого вывода модели. Сравнение и вопрос не создают оценку, attempts, reviews, карточки или mastery. Автоматического балла за применение нет.
- Язык берётся из направления. Русские названия языка (`Russian`, `ru`, `ru-RU`, `Русский`) получают явное поручение перевести все объясняющие поля; остальные названия передаются как данные с инструкцией перевода. Все языки/модели в рамках этого среза не проверялись.

## Ошибки и сохранение

- Пустое/одинаковое название, отсутствие выбора и чужой/удалённый источник блокируют запрос. Нет направления — остаётся прежнее пустое состояние репетитора. Ошибка поиска, неверный JSON/число строк, неподдержанная ссылка или текст без подтверждения не добавляют сообщений.
- Генерация выполняется только по кнопке, без автоматического retry. При закрытии окна или выходе из репетитора поздний результат отбрасывается и не записывается. Уже отправленный запрос может завершиться у провайдера.
- Перед записью проверяются актуальные направление/узел карты, принадлежность всех выбранных источников и снимки всех их страниц. Изменённые/удалённые материалы требуют нового сравнения. Очередь записи остаётся в исходном пространстве; удалённое направление не восстанавливается.
- Два сообщения записываются атомарно. При ошибке диска результат остаётся в текущем окне, **Повторить запись в беседу** использует тот же результат/IDs, без повторной генерации и дублей. Повторная запись уже сохранённого результата не удаляет закладку. Новое сравнение позволяет отбросить несохранённый результат.
- Сохранённые ответы и цитаты остаются историческими, если источник позднее меняется/удаляется; P2 показывает прежнее предупреждение об изменившихся подтверждениях.

## Код

- `desktop/src/ai/sourceComparison.ts`: входная/ответная схемы, отдельный сбалансированный поиск, проверка canonical результатов индекса, запрет ссылок между сторонами, no-evidence без inference, ограниченный source-only prompt, текст результата и атомарный/idempotent append двух сообщений.
- `features/tutor/SourceComparisonDialog.tsx`: выбор понятий/источников, прогресс/ошибки, две колонки с цитатами, повтор записи, P2-закладка, отмена позднего результата. Параметры сворачиваются после генерации; результаты доступны в светлой/тёмной теме и при уменьшении ширины окна.
- `Tutor.tsx` / `App.tsx`: кнопка, вход в библиотеку, закрытие сравнения при новом contextual draft P1. Прежняя обычная отправка репетитора не переписывается.
- Данные используют существующие `message.content`, `replyTo`, `citations`, `provenance`, `savedAt` и optional `topicId`. Новых зависимостей, SQL-таблиц/миграций или обязательных полей backup нет. После reload результат читается как обычный ответ; структурированный редактор сохранённой таблицы и универсальный экспорт остаются вне MVP.

## Проверка

Результат: **75 TypeScript unit + 18 native Rust + 47 production-browser E2E passed**; дополнительно прошёл **1 live smoke на настоящей локальной qwen3:4b**, с синтетическими английскими заметками, русским результатом и canonical ссылками обеих сторон. В стандартном прогоне пропускаются 5 opt-in Vitest integrations и 1 аккаунтный Rust test; из них новый comparison smoke выполнен отдельно. Браузерные ответы ИИ подменены, проверки всех облачных моделей/языков не заявляются. TypeScript/Vite build и Rust formatting прошли.

Browser E2E используют production-сборку с подменёнными ответами ИИ и проверяют весь путь, закладку/reload, цитаты/P1, две темы, ошибки записи/модели, валидацию и отмену. Native Rust проверяет reopen пары/закладки и rollback всей пары при ошибке второй записи. Live qwen3:4b проверяет обе группы ссылок, русский текст и валидность сохранения.
