# Какие идеи NotebookLM нужны ConceptLoom

Проверено 25 октября 2026. Результат — продуктовый разбор и план, не реализация функций. Код приложения не изменён.

Последующее выполнение плана: **MVP P1–P5 реализованы в Desktop 0.3.2–0.3.6**: [P1](p1-source-tutor.md), [P2](p2-saved-explanations.md), [P3](p3-map-tutor.md), [P4](p4-source-flashcards.md), [P5](p5-source-guide.md). Следующий шаг — P6. Оценки и сравнение ниже отражают исходный разбор до реализации.

## 1. Что изучено и что представляет собой проект

Репозиторий доступен локально и через Git. После `git fetch origin` подтверждено: **`origin/main` — Desktop 0.1.1, коммит `5c5a152`; рабочая `codex/production-audit` — 0.3.1, `5ad6c1b`, на 11 коммитов впереди**. Ниже анализируется последняя рабочая версия. Для разработки от `main` сначала необходимо включить существующие изменения пространств, источников, дизайна, провайдеров и аудита. Их не следует писать заново.

1. ConceptLoom — Windows-приложение для обучения по своим материалам: Locate → Weave → Build, проверка понимания и отложенное воспроизведение.
2. Основной путь: workspace → PDF/текст → учебное направление → зависимости понятий → занятие → ответы → FSRS-повторение.
3. Данные: извлечённые страницы, фрагменты, цитаты, цели, темы, уроки, попытки, уверенность, ошибки, карточки и история репетитора.
4. React 19/TypeScript/Zod, Tauri 2/Rust, SQLite FTS5/BM25, React Flow и `ts-fsrs`; браузер — отдельное preview, не размещённый веб-сервис.
5. Ollama выполняет локальный inference; облако подключается официальными CLI через аккаунты с согласием. Это не интеграция с API NotebookLM.
6. Поиск уже возвращает до шести фрагментов; приложение проверяет принадлежность citation ID, но ещё не привязывает каждое утверждение ответа к доказательству.
7. Слабые места: нет удобного перехода от страницы к репетитору, сохранения лучших ответов и предварительного выбора генерируемых карточек; есть лимиты контекста, отсутствие retry/cancel и экспорта/восстановления.
8. Предполагаемая аудитория — самостоятельные учащиеся, студенты и взрослые с собственными учебными материалами. Это гипотеза по сценариям кода, не результат интервью.

Прочитаны актуальные `App.tsx`, библиотека/цитаты/индекс, Tutor, KnowledgeMap, StudyHub, уроки и карточки, mastery/FSRS, схемы, провайдеры/промпты, repository/changes/workspaces, native source index и миграция 002, README и прежний аудит. Ранее полный аудит завершён в этой же ветке. Сейчас приложение не запускалось, новый hands-on тест NotebookLM под аккаунтом не выполнялся: внешние факты проверены по публичной документации и обзорам.

Рабочие ограничения: local-first сохраняется, платный API не обязателен, новые сервер/аккаунты синхронизации не нужны. Размер команды и денежный бюджет не заданы; оценки ниже исходят из одного разработчика и минимальных постоянных расходов. S ≈ одна рабочая сессия, M ≈ несколько сессий, L ≈ отдельный этап; это ориентиры, не обязательства по срокам.

## 2. Что у Google есть сейчас

Google объявил переименование NotebookLM в **Gemini Notebook 16 июля 2026**. Далее использую привычное название NotebookLM; доступность экспериментальных функций зависит от аккаунта и плана. [Официальное объявление](https://blog.google/innovation-and-ai/products/gemini-notebook/notebooklm-gemini-notebook/).

- **Источники и chat:** выбор материалов, ответы с переходом к подтверждающим фрагментам, Source Guide, быстрый поиск источников и Deep Research. Поддерживаются также форматы за пределами ваших PDF/TXT/Markdown: документы, таблицы, изображения, аудио, URL и транскрипты YouTube. [Chat](https://support.google.com/gemininotebook/answer/16179559?hl=en), [источники и исследование](https://support.google.com/gemininotebook/answer/16215270?hl=en).
- **Studio:** notes, Audio/Video Overviews, Mind Maps, reports, flashcards, quizzes, infographics, slide decks и data tables; таблицы можно выгружать в Sheets. [Официальный перечень Studio](https://support.google.com/gemininotebook/answer/16206563?hl=en), [Data Tables](https://blog.google/innovation-and-ai/models-and-research/google-labs/notebooklm-data-tables/).
- **Аудио:** Deep Dive, Brief, Critique и Debate; голосовое присоединение к Audio Overview — отдельный интерактивный режим, документация ограничивает его английским. [Audio Overview](https://support.google.com/gemininotebook/answer/16212820?hl=en).
- **Интерактивное обучение:** узел Mind Map можно отправить в chat; карточки помнят Got it/Missed it и позволяют вернуться к ошибкам; chat имеет Learning Guide, язык вывода настраивается. [Mind Maps](https://support.google.com/gemininotebook/answer/16212283?hl=en), [карточки и quizzes](https://support.google.com/gemininotebook/answer/16958963?hl=en), [язык](https://support.google.com/gemininotebook/answer/16261963?hl=en).
- **Новее базового списка:** Google описывает экспериментальные web/code-действия и дополнительные файлы-результаты. Отдельно в **Gemini Apps**, а не просто в обычных карточках NotebookLM, появились study notebooks с диагностикой, персональными уроками и tracking. Нельзя заявлять, что у Google совсем нет адаптивного обучения или сохранённого прогресса. [Обновление research](https://blog.google/innovation-and-ai/products/notebooklm/better-research-notebooklm/), [study notebooks](https://support.google.com/gemini/answer/16972047?hl=en).

Обзоры использованы как наблюдения, не как спецификация. [iTechGuides, 18 августа 2026](https://www.itechguides.com/i-tested-notebooklm-for-academic-technical-and-general-research-heres-where-it-actually-helps/) подчёркивает зависимость качества от материалов и то, что цитата не доказывает правильность интерпретации. [Cybernews, обновление 6 января 2026](https://cybernews.com/ai-tools/notebooklm-review/) сообщает об ограничениях offline и ошибках визуального текста. Январский обзор старше текущих возможностей: его утверждение о ручном обновлении источников нельзя обобщать — нынешняя документация Google прямо описывает auto-sync Drive. Сведения о новых функциях взяты из Google, а не из этих обзоров.

### Три направления, где ConceptLoom может быть лучше

1. **Полноценное локальное обучение.** Ollama + SQLite позволяют читать, спрашивать и повторять без передачи материала в облако после установки модели. У Google можно скачать некоторые результаты для offline, но это не локальный inference; облачные функции и аккаунт остаются частью его модели. Возможность выбора local/cloud у вас уже есть. [Mobile/offline у Google](https://support.google.com/gemininotebook/answer/16296687?co=GENIE.Platform%3DiOS).
2. **Проверяемое понимание вместо доверия красивому ответу.** Ссылка на фрагмент помогает проверить объяснение, но не гарантирует его истинность. Ваш выигрыш — короткая проверка recall/application/transfer после разбора с видимой опорой на текст. Это продуктовая возможность, не доказанное превосходство качества ваших моделей. [Ограничения grounding в свежем обзоре](https://www.itechguides.com/i-tested-notebooklm-for-academic-technical-and-general-research-heres-where-it-actually-helps/).
3. **Прозрачное долговременное повторение.** У Google уже есть результаты карточек, повтор ошибок и study notebooks. На просмотренных страницах не описан FSRS-контракт. У вас есть явный scheduler и правило delayed retrieval до Mastered — стоит показывать пользователю, почему и когда вернётся карточка, и сохранять эту логику. Не рекламировать «у конкурента нет прогресса». [Текущие карточки Google](https://support.google.com/gemininotebook/answer/16958963?hl=en).

## 3. Фильтр возможностей

ADOPT — взять принцип, который подходит почти без изменений; «уже есть» означает сохранить, не дублировать. ADAPT — изменить под обучение и local-first. SKIP — не включать в ближайшую дорожную карту.

- **Notebooks / много источников — ADOPT, уже есть:** workspace + libraries + `SourceScope`; не добавлять третий уровень «ноутбуков» поверх них.
- **Source-grounded chat — ADOPT, уже частично есть:** развивать `answerFromSources`, а не подключать отдельный RAG-сервис.
- **Inline citations / точный переход — ADAPT, P1:** нынешний `Citations` показывает список снимков; нужен контекстный переход и затем ссылки у конкретных абзацев.
- **Source Guide — ADAPT, P5:** краткий паспорт с явным покрытием страниц; не выдавать шесть поисковых фрагментов за весь документ.
- **Saved notes — ADAPT, P2:** сначала сохранённые ответы с исходными цитатами, без автоматического превращения ИИ-текста в новый первичный источник.
- **Flashcards — ADAPT, P4:** маленький набор по выбранному фрагменту → просмотр/редактирование → существующий FSRS.
- **Quizzes — ADAPT, P4 после карточек:** использовать существующие задания/attempts, не строить второй движок оценивания.
- **Interactive Mind Map — ADAPT, P3:** добавить «Спросить об этом» на существующую карту зависимостей; ассоциация и prerequisite — разные связи.
- **Reports / study guide — ADAPT, P5/P6:** конкретный паспорт или сравнение с цитатами, без универсальной Studio из десятка форматов.
- **Data Tables — ADAPT, P6:** ограниченная таблица сравнения понятий, а не произвольные spreadsheets и расчёты.
- **Learning Guide — ADOPT, уже есть:** текущие system/lesson prompts, диагностика и четыре измерения понимания; поддерживать их, а не копировать новое имя режима.
- **Multi-language output — ADOPT, частично есть:** проводить `course.explanationLanguage` через новые генерации; не обещать качество любого языка на маленькой локальной модели. Перевод UI — отдельная задача.
- **Fast Research — SKIP сейчас:** сетевой поиск, получение и очистка URL потребуют новой разрешённой network-границы; сначала сделать полезнее уже импортированные материалы.
- **Deep Research — SKIP:** автономный multi-step browsing конфликтует с текущим отключением инструментов в account bridge, offline-режимом и предсказуемым расходом лимита.
- **Audio Overviews, все форматы — SKIP:** полноценные двухголосые обзоры требуют TTS, хранения аудио, фоновых задач и проверки произношения; пока не закрывают путь «понял → проверил → повторил».
- **Interactive audio / live voice — SKIP:** добавляет STT/TTS, микрофон, задержки и real-time orchestration, которых нет в `AIProvider`.
- **Video Overviews — SKIP:** нет media pipeline, renderer и фонового job lifecycle; высокая трудоёмкость относительно текущих проблем обучения.
- **Infographics — SKIP:** генеративные картинки не заменяют уже существующий редактируемый React Flow, а подписи/формулы нужно отдельно проверять.
- **Slide Decks — SKIP:** создание презентаций — другой основной сценарий, требует редактора и экспорта; у текущих пользователей не подтверждён спрос.
- **Все новые форматы импорта сразу — SKIP:** OCR/аудио/YouTube/Drive — разные подсистемы, не одна небольшая доработка `accept`; сначала измерить реальные неудачные импорты. Ручной PDF/TXT/paste сохраняется.
- **Sharing / Drive / межсервисный sync — SKIP:** потребуются backend, авторизация, ACL и разрешение конфликтов, отсутствующие в локальной архитектуре.
- **Cloud computer / agentic code outputs — SKIP:** противоречат текущему запрету инструментов/кода в генерации и требуют другой модели безопасности.

Текущие возможности Google в этом списке подтверждаются страницами из раздела 2; решения ADOPT/ADAPT/SKIP — мои выводы из кода и ограничений проекта.

## 4. Шесть идей, которые стоит делать

Порядок уже учитывает ценность/усилия. Грубая оценка для сравнения: high=3, medium=2; S=1, M=3, L=8. Это не измеренный ROI. При равенстве выше стоит идея, снимающая больше трения или создающая основу следующим. Стоимость ниже — на одно действие, без автоматических retry.

### P1. Обсудить текущий фрагмент — ПЕРВОЙ

**Проблема:** материал открыт в Sources, но вопрос репетитору приходится формулировать заново; контекст страницы теряется.

**Путь:** в `Library.tsx` рядом с текущей страницей и в `Citations` добавить «Разобрать с репетитором». Выбрать направление при его отсутствии → открыть Tutor с чипом «Лекция · с. 7» и черновиком вопроса. Передача не запускает inference сама. Пользователь отправляет вопрос; ответ сохраняет цитату. В следующем малом шаге `answerFromSources` возвращает `sections[{text,citationIds}]`, и ссылка ставится рядом с абзацем.

**Состояния:** нет читаемого текста — действие недоступно с объяснением; слишком большая страница — предложить конкретный фрагмент; loading — контекст остаётся видим; ошибка/нет модели/нет согласия — сохраняются черновик и выбранный фрагмент, доступен retry. Источник удалён/изменён — показать снимок как устаревший и предложить повторный выбор, не подменять другой страницей.

**Код/данные:** новый *предлагаемый* `TutorIntent` в `App.tsx`: workspaceId, courseId, sourceId, page/chunkId, excerpt, requestId; callback в `Library.tsx` и `SourceContext.tsx`; обработка в `Tutor.tsx` и optional pinned context в `ai/sourceLearning.ts`. Проверять workspace и существование источника до отправки. Не менять постоянно `course.sourceScope` из-за одноразового вопроса. В MVP схема БД не меняется; snapshot citations уже существует. Для sections — optional поле в `messageSchema`, старый `content` остаётся fallback; Rust хранит payload без новой таблицы.

**Модель/цена:** существующий `AIProvider`, Ollama по умолчанию; 0 запросов при навигации, 1 после отправки. Ориентир 2–4k input / до 700 output tokens. Локальный API-счёт $0; время и электричество не нулевые. При выборе аккаунта расходуется его лимит.

**Риски:** pinned-фрагмент должен реально попасть в prompt; обычный повторный BM25-поиск может его потерять. Ссылка на абзац не доказывает entailment: не называть ответ «проверенным». Исходный PDF-бинарник сейчас не сохраняется, координат выделения нет — MVP открывает извлечённый текст и страницу, а не обещает highlight в оригинальном PDF.

**S / high, 3.0. Одна сессия:** одна кнопка из текущей страницы → Tutor с явным ограниченным контекстом и сохранением черновика; существующая citation UI. Приёмка: контекст не смешивается между workspace и переживает ошибку запроса. Абзацные citations — следующий шаг этой же идеи, не условие первой поставки.

### P2. Сохранить полезный ответ

**Проблема:** хорошее объяснение тонет в истории, его приходится искать или генерировать повторно.

**Путь:** кнопка «Сохранить» под ответом → «Сохранённые объяснения» в StudyHub → открыть сообщение с цитатами → «Убрать из сохранённых». Это curated-срез истории, а не ещё одна библиотека источников.

**Состояния:** пусто — предложить сохранить ответ в Tutor; короткое состояние сохранения; ошибка commit оставляет кнопку/данные прежними, показывает retry. После удаления источника цитата доступна как исторический excerpt с пометкой; не изображать его актуальной версией.

**Код/данные:** optional `savedAt` в `messageSchema` (`types/state.ts:171`), toggle в `Tutor.tsx`, небольшой список в `StudyHub.tsx`. Проверка — existing `repository.save` и scoped commit. Native `ai_messages` хранит JSON payload, поэтому для такого поля SQL-миграция не требуется. Не переиспользовать бездумно legacy `notes`: они привязаны к course и мигрировали в sources, а не образуют готовую новую workspace-noteboard.

**Модель/цена:** 0 AI-запросов, $0 API. Сохраняется имеющийся content/citations. Редактируемые авторские заметки и экспорт — позднее, не скрытая часть MVP.

**Риски:** удаление course по текущей модели удалит его сообщения — явно обозначить зависимость; AI-ответ не индексировать автоматически как первичный source. Учесть общий snapshot, ограничить список/показывать первые записи.

**S / high, 3.0. Одна сессия:** save/unsave + список, scoped по workspace/направлению, сохранение после reopen. Проверка не должна изменять mastery и расходовать inference.

### P3. Спросить об узле карты

**Проблема:** пользователь видит связь, но не понимает, почему она существует или что надо знать раньше.

**Путь:** выбранный узел KnowledgeMap → «Почему это связано?» → Tutor с темой, предпосылками и источниками. Один дополнительный быстрый вариант — «Объясни на примере». Не генерировать новую mind map.

**Состояния:** пустая карта сохраняет нынешний CTA; для locked-узла можно объяснить prerequisite, но нельзя ставить mastery или открывать gated-урок; loading/error — общие с P1, выбранный узел остаётся тем же.

**Код/данные:** `KnowledgeMap.tsx:24` уже имеет selected topic; callback в App и `TutorIntent` P1; `tutorContext` уже принимает Topic. Схема БД не меняется. Сохранять смысл `dependsOn` и проверку DAG: тематическая ассоциация не становится новой prerequisite-стрелкой автоматически.

**Модель/цена:** навигация 0; объяснение 1 existing chat/structured request, ориентир 1–3k input / до 700 output. Local $0 API; cloud — лимит выбранного аккаунта.

**Риски:** отправить именно выбранный узел, не первый frontier; сохранить scope и не утверждать, что prerequisite доказан только потому, что модель его упомянула.

**S / medium, 2.0. Одна сессия после P1:** одна кнопка и contextual draft. Приёмка: тема/цитаты соответствуют узлу, объяснение не меняет attempts.

### P4. Две карточки из фрагмента

**Проблема:** сейчас auto-карточки появляются как побочный результат полного урока; чтобы закрепить один абзац, приходится создавать урок или вручную переписывать текст.

**Путь:** текущий фрагмент → «Закрепить» → выбрать направление и при желании тему → получить 2 черновика → исправить/выбрать → «Добавить в повторение». Позднее тем же входом создавать маленькую проверку recall/application/transfer через существующие уроки.

**Состояния:** нет текста/направления — конкретный CTA; loading показывает 2 запрошенные карточки, не бесконечную генерацию; неверный JSON — не сохранять ничего; пустой выбранный набор — disabled; ошибка commit — черновики остаются; повтор сохранения не создаёт дубли. Показывать оригинальный фрагмент рядом с ответами.

**Код/данные:** новая *предлагаемая* `ai/sourcePractice.ts` с Zod-схемой и existing `sourcePolicy`/`resolveCitations`; entry point из Library/SourceContext, preview-editor переиспользует форму Flashcards. Принятые карточки создаются через `learning/reviews/newCard`, сохраняют citations/createdBy. Если topic не выбран, `topicId:null`: это разрешено текущей схемой и не даёт произвольному понятию mastery. Для MVP новых таблиц нет; дедупликация по requestId/ID черновика при повторном commit и предупреждение по одинаковому front.

**Модель/цена:** 1 bounded structured-вызов, ориентир 1–2k input / 400–900 output. Local $0 API; cloud quota. Не генерировать колоду целиком и не повторять молча неудачную генерацию.

**Риски:** маленькая модель может составить вопрос с подсказанным ответом; редактор/отклонение обязательны. Не портить FSRS существующих карточек и не выдавать просмотр черновика за retrieval. Полный quiz должен писать существующие attempts, а не второй несопоставимый score.

**M / high, 1.0. Одна сессия:** только 2 карточки, preview, ручной выбор, existing FSRS; quiz и автоматический подбор по ошибкам остаются следующими срезами. Приёмка: 1 запрос → 2 черновика → выбрана 1 → сохранена 1, её due/reps корректны после reopen.

### P5. Паспорт источника с честным покрытием

**Проблема:** после импорта длинного материала непонятно, о чём спрашивать и насколько документ подходит к цели.

**Путь:** Sources → выбранный материал → «Обзор раздела»: 3 тезиса, 3 термина, 3 вопроса для начала и указание разобранных страниц. Клик вопроса использует P1. Вычислять по нажатию, а не при каждом импорте/открытии.

**Состояния:** до генерации — содержимое и CTA; loading — диапазон обрабатываемых страниц; нечитаемый/слишком большой источник — выбрать раздел; ошибка не ломает импорт; изменился текст — пометка «обзор устарел», повтор по желанию.

**Код/данные:** Library + новый *предлагаемый* `ai/sourceGuide.ts`. Читать выбранные страницы напрямую; `generateGrounded(overview=true)` с fallback первых двух чанков не годится как честное резюме всего PDF. Для MVP только короткий раздел в допустимом контексте. Optional `guide` в `sourceSchema`: sourceHash, coveredPages/chunkIds, outputLanguage, model, promptVersion, createdAt, result; existing source payload хранит JSON, FTS переиндексируется только при изменении pages. Длинный whole-document map/reduce потребует очереди, cancel, per-page budget и отдельной фазы.

**Модель/цена:** 1 bounded structured-вызов по небольшому разделу, около 2–3k input / 500–1000 output. Local $0 API. Cache по hash/lang/promptVersion предотвращает повторные расходы. Обзор всей книги не включён в эту оценку.

**Риски:** пропуск оговорок и формул; текстовый PDF parser не гарантирует сохранение таблиц. Покрытие показывается пользователю, рекомендации не должны представлять неполный раздел как полный курс.

**M / medium, 0.67. Одна сессия:** одна выбранная короткая глава, три тезиса/вопроса, cache и переход к Tutor; никакой фоновой обработки всей библиотеки. Приёмка: изменённый текст помечает cache устаревшим, повторное открытие не запускает inference.

### P6. Сравнить два понятия с доказательствами

**Проблема:** читатель путает похожие механизмы — например, B-tree/B+ tree или atomicity/isolation; обычный общий ответ скрывает различия и пробелы источника.

**Путь:** Tutor → «Сравнить» → два понятия + выбранные источники → 3–5 строк: критерий, A, B, подтверждающие цитаты. Клетка без материала говорит «не найдено в выбранных источниках». В конце один вопрос на применение, без автоматического балла.

**Состояния:** нет источников — выбрать, меньше двух понятий — форма не отправляется; loading один; частичное покрытие остаётся частичным; invalid JSON/чужие IDs — retry, без записи некорректной таблицы; сохранение через P2.

**Код/данные:** новый *предлагаемый* `ai/sourceComparison.ts`, отдельный поиск по A и B в `sourceIndex`, сбалансированный лимит фрагментов в общем бюджете, schema `rows[{criterion,a:{text,citationIds},b:{text,citationIds}}]`. Existing `AIProvider.structured`, resolver каждого cell. На MVP хранить читаемый текст в message.content + citations; позже optional структурированный payload для интерактивной таблицы, без XLSX/CSV-движка. Общие знания только явно в mixed-режиме.

**Модель/цена:** 2 локальных поиска + 1 structured-вызов, ориентир 2–4k input / 700–1200 output. Local $0 API, cloud quota. Поиск не требует vector DB; сначала BM25 и маленький словарь терминов/переформулировка по подтверждённым no-hit кейсам.

**Риски:** false equivalence, неподтверждённые числа, поиск по синониму не находит нужный текст. «Не найдено» не означает «этого нет в книге». Не строить summary всего документа из top-6 results.

**M / medium, 0.67. Одна сессия:** фиксированные 2 понятия, до 3 строк, текстовая отрисовка с citation-кнопками; без универсального конструктора таблиц. Приёмка: удалённое доказательство даёт missing cell, а не выдуманную симметричную характеристику.

## 5. Порядок поставки и ограничения

**До новых идей:** включить существующую 0.3.1 в выбранную release-ветку; не разрабатывать поверх старого main. Для AI-доработок привести response limits к сохраняемым 20 000 символов (`sourceLearning.ts` сейчас допускает два поля по 12 000), добавить сохранённый draft и retry без дубля вопроса. Не нужно ждать полной переработки хранения или большого export-проекта ради P1/P2.

1. **P1 — первой:** самый короткий путь от вашего существующего PDF-импорта к полезному учебному действию; не нужен сервер, API-контракт, новая таблица или другой LLM. Даёт общий contextual intent для P3/P4/P5.
2. **P2:** сохранение уже оплаченного/сгенерированного знания, ноль inference; высокая ценность за небольшой change set.
3. **P3:** дешёвая интеграция с готовым P1; усиливает вашу отличительную карту prerequisites.
4. **P4:** превращает чтение в повторение, переиспользуя FSRS; после проверки пригодности P1 в реальной работе.
5. **P5:** уменьшает растерянность после импорта; только при честном покрытии и cache.
6. **P6:** полезен для сложных предметов, но стоит дождаться наблюдаемых вопросов «в чём разница».

Если есть только одна сессия — поставить P1, а не половину всех шести. Первая ручная приёмка: открыть PDF → с. 7 → «Разобрать» → вопрос → ответ с тем же фрагментом → вернуться к чтению. Метрики: завершение этого пути, доля no-evidence/retry, ручная проверка цитат, повторное использование сохранённых ответов. Целевые проценты без исходной аналитики не назначаю.

**Три привлекательные ловушки:** (1) полноценная podcast/video Studio — media pipeline дороже текущей отдачи; (2) автономный Deep Research с инструментами CLI — другая network/security-модель и непредсказуемые multi-call затраты; (3) второй тип Mind Map — дублирует React Flow и путает «связано по теме» с «надо знать раньше».

Общий контракт всех MVP: не более одного модельного вызова на явное действие; existing Ollama `qwen3:4b` — базовый кандидат, качество проверяется русскими учебными примерами, не предполагается достаточным заранее. Аккаунтный провайдер — добровольная альтернатива по existing consent, без silent fallback. Отдельные Gemini/Claude/OpenAI API и API NotebookLM не требуются. CLI-подписка не даёт нашему приложению цену в $/token, поэтому денежный тариф облачного действия не выдумывается. Оценки tokens — плановые диапазоны, не benchmark; общий prompt/output надо удерживать в текущем `num_ctx:8192` и фактическом `num_predict`.

Для каждого среза достаточно targeted unit-теста schema/scope и одного E2E его критического пути; новые библиотеки не нужны. Базовая проверка качества: материал с ответом, материал без ответа, чужой workspace, изменённый источник, offline/отозванное согласие, invalid JSON и повтор commit. Сгенерированное объяснение/просмотр/сохранение сами по себе никогда не увеличивают mastery.
