## Что получает пользователь

- У выбранного понятия карты, перед блоком результатов, — «Почему это связано?» и «Объясни на примере». Для понятия без предпосылок первый вариант называется «С чего начать?».
- Переход открывает редактируемый черновик. Запрос ИИ выполняется только после «Отправить». В контексте видны точное понятие, описание и предпосылки; репетитор не подменяет выбранное понятие первым доступным.
- «Вернуться к карте» возвращает выбор того же узла. Нативный список «Выбранное понятие карты» позволяет выбирать понятия с клавиатуры.
- Заблокированное понятие можно обсудить; занятие остаётся недоступным. Объяснение не создаёт attempts, уроки, карточки или reviews, не меняет mastery и dependsOn.
- Источники направления и режим ответа сохраняются. Цитаты узла используются только внутри уже выбранных источников. Устаревшая цитата выбранного источника блокирует запрос до исправления контекста. Удалённый/невыбранный источник не отправляется; при отсутствии подтверждений в sources-only возвращается прежнее сообщение о недостатке источников, без вызова ИИ.
- Без выбранных источников явно показано, что ответ будет из знаний модели и без цитат. Связи карты обозначены как учебный план; модель не должна выдавать их за доказанные источниками факты.
- Переписка в контексте понятия отделена от других узлов. После неудачного запроса вопрос и его topicId восстанавливаются после перезапуска; повтор не дублирует вопрос. Поздний ответ остаётся у исходного узла и не очищает новый черновик.
- Ответы сохраняются через P2, с исходным вопросом и цитатами. Редактируемый, ещё не отправленный черновик переживает навигацию текущего запуска; после перезапуска восстанавливаются только уже записанные вопросы без ответа, как в P1.

## Как устроено

`KnowledgeMap.tsx` получает выбранное понятие из App. Выбор на canvas и в списке обновляет один ID. Callback создаёт новый TutorDraft с topicId и черновиком вопроса, без записи учебных результатов и без inference.

`features/tutor/mapContext.ts` проверяет принадлежность понятия направлению и активному пространству, создаёт два варианта вопроса и разрешает цитаты внутри текущего scope. `tutorContext` добавляет описание выбранного понятия и до 24 предпосылок с их статусом; это контекст обучения, а не evidence.

`Tutor.tsx` показывает явный контекст карты, использует его в обычном chat и в source-grounded ответе, фильтрует переписку по topicId. В `answerFromSources` цитаты узла получают приоритет, затем добавляются результаты поиска по названию узла, предпосылкам и вопросу. Дубликаты chunks убираются; максимум 6 фрагментов. Ответ может ссылаться только на реально переданные chunks через прежний `resolveCitations`.

`messageSchema` получает необязательный topicId в существующем JSON payload. Старые сообщения остаются валидными; SQL-таблицы, версия состояния 2 и миграции не меняются. Прежняя проверка repository запрещает topicId другого направления/несуществующего понятия; новая проверка запрещает одновременно контекст карты и pinned-фрагмент. `restoreTutorDraft` восстанавливает map-вопрос так же, как вопрос по источнику. Очередь scoped commits и защита нового draft ID от позднего ответа переиспользуются.

## Проверка

Результат: **47 TypeScript unit + 15 native Rust + 26 production-browser E2E passed**. 3 opt-in AI проверки Vitest и 1 аккаунтная проверка Rust пропущены. TypeScript/Vite build и `cargo fmt --check` прошли. После финальной правки расположения кнопок и снятия контекста повторно прошёл весь набор из 26 E2E.

Из `desktop`:

```powershell
npm test
npm run build
$env:PLAYWRIGHT_PREVIEW = '1'
npx playwright test --workers=1 --reporter=line
cd src-tauri
cargo fmt --check
cargo test --lib
```

Unit: явный locked-узел вместо frontier; предпосылки и изоляция; восстановление topicId без дублирования; чужое/удалённое понятие; конфликт двух контекстов; scope; changed evidence; invented citations; 0 inference при отсутствии evidence.

Native SQLite: существующий round-trip тест расширен topicId — сохранённое объяснение и его цитаты/привязка переживают повторное открытие временной БД и снятие закладки, cascade удаляет их вместе с направлением. Пользовательская БД не открывается.

E2E: locked-узел → черновик → ошибка → reload/retry → ответ с цитатой → P2 save → тот же locked-узел; обычный chat без источников; изоляция направлений/пространств; поздний ответ при новом узле; changed evidence; sources-only без совпадений; пустая карта. Проверяются тёмная тема 1366×768 и светлая 1000×700, отсутствие горизонтального переполнения. Запросы ИИ в browser-тестах подменены детерминированными ответами; реальный облачный или локальный inference для этих проверок не нужен.

Ручная приёмка: выбрать узел, который требует ещё не освоенную предпосылку → «Почему это связано?» → проверить название/предпосылки → отправить → прочитать цитату → «Вернуться к карте» → занятие всё ещё заблокировано. Повторить «Объясни на примере» при scope=none, затем переключить направление и убедиться, что его черновик отдельный.

Установщик: `desktop/releases/ConceptLoom_0.3.4_x64-setup.exe`. Установка поверх пользовательских данных автоматически не запускается.

## Границы

Граф prerequisites остаётся прежним DAG; новые связи автоматически не создаются. Контекст узла не доказывает истинность связей и не оценивает ответы. Если сам узел был отредактирован, новые запросы используют актуальное название/описание/предпосылки, а сохранённые ответы остаются историческими сообщениями. До 24 предпосылок попадает в prompt; общее число передаётся отдельно. Карточки из фрагмента относятся к следующему P4.
