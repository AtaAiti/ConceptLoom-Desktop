# P4: две карточки из выбранного фрагмента

Desktop 0.3.5. Четвёртый срез из [продуктового плана](notebooklm-product-review.md), поверх [P1](p1-source-tutor.md), [P2](p2-saved-explanations.md) и [P3](p3-map-tutor.md). Следующая сессия — **P5: паспорт источника с честным покрытием**, затем P6.

## Пользовательский путь

1. В источниках, предпросмотре страницы или открытой цитате нажать **«Закрепить · 2 карточки»**.
2. Если страница длинная — выбрать один ограниченный фрагмент. Выбрать направление; привязка к понятию необязательна и по умолчанию отсутствует. Источники/режим направления не меняются.
3. **«Создать 2 карточки»** выполняет один structured-запрос к уже выбранному ИИ. Отправляется этот фрагмент, без других страниц, переписки и материалов других пространств.
4. В окне рядом с оригинальным фрагментом проверить два черновика, исправить вопросы/ответы, снять выбор ненужных. Повторяющиеся вопросы отмечены предупреждением, без скрытого удаления карточек.
5. **«Добавить в повторение (N)»** сохраняет только выбранные карточки с исходной цитатой, `createdBy: ai` и новым расписанием FSRS. До сохранения карточек в данных нет; существующие интервалы, reviews, attempts и mastery не меняются.
6. Открыть карточки или закрыть окно. После перезапуска они доступны в обычном повторении; открыть ответ, прочитать цитату и оценить воспроизведение. Только эта явная оценка создаёт review и меняет расписание.

## Обработка ошибок

- Нет текста — предложена другая страница; нет направления — кнопка его создания; длинная страница не отправляется целиком автоматически.
- Генерация выполняется только по кнопке, показывает «Создаём 2 черновика…». Неправильный JSON, не две карточки, пустой/слишком большой ответ, одинаковые вопросы и чужой citation ID не дают сохранить некорректный результат. Автоматического повторного inference нет.
- Старый фрагмент из цитаты проверяется перед запросом. Изменённый, удалённый или чужой фрагмент блокирует генерацию. Повторная проверка источника и направления выполняется в актуальном состоянии очереди сохранения.
- Без выбранных карточек или с пустыми вопросом/ответом выбранной карточки сохранение недоступно. Невыбранный черновик может быть пустым и не мешает сохранить другой.
- При ошибке записи выбранные карточки, правки и их IDs остаются в окне. Повторное добавление не вызывает ИИ и не создаёт дубли; уже сохранённая/повторённая карточка не перезаписывается.
- Закрытие генерации или переключение пространства отбрасывает поздний результат; он не открывает окно заново и не записывает карточки. Уже отправленный запрос может завершиться у провайдера; API отмены существующих providers не менялся.

## Реализация

`ai/sourcePractice.ts`: схема ровно двух разных карточек, ограниченные ответы, source-only политика, разрешение только переданного chunk ID. IDs черновиков создаёт приложение. `appendSourceCards` разрешает направление/понятие в исходном пространстве и повторно проверяет фрагмент, создаёт только отсутствующие выбранные IDs через `newCard`, сохраняет canonical citation. При `topicId:null` карточка не записывает evidence произвольному понятию.

`features/flashcards/SourcePracticeBridge.tsx`: общий entry point и окно config → generating → review → saving → success. Epoch защищает от позднего результата после закрытия/смены пространства; in-flight guard и стабильные IDs защищают от повторного добавления. Сохранение использует прежний scoped commit из App. Фрагменты страницы вычисляются через memo, чтобы ввод в редактор не пересоздавал chunks длинного PDF.

`CardFields.tsx` выделен из прежнего редактора Flashcards и переиспользуется без изменения его подписей/содержимого. `library/sourceSelection.ts` выделяет прежнюю логику P1 для одинаковых правил выбора страницы/цитаты в P1 и P4. Library, SourceDialogs и Citations получают новую кнопку. Новых зависимостей, SQL-таблиц, полей схемы Workspace или миграций нет.

## Проверка

Результат: **54 TypeScript unit + 16 native Rust + 33 production-browser E2E passed**. 3 opt-in AI проверки Vitest и 1 аккаунтная проверка Rust пропущены. TypeScript/Vite build и Rust format прошли; после исправления ширины окна повторно прошёл весь browser-набор, включая P1–P3 и ручное создание карточки.

Из каталога `desktop`:

```powershell
npm test
npm run build
$env:PLAYWRIGHT_PREVIEW = '1'
npx playwright test --workers=1 --reporter=line
cd src-tauri
cargo fmt --check
cargo test --lib
```

Unit: ровно один запрос с одним фрагментом, две карточки и app IDs; неправильная схема/число/повторы/чужие citations; чужой/удалённый target и source; сохранение только выбранной отредактированной карточки; FSRS без сброса существующих интервалов; отсутствие mastery/attempts/reviews; idempotent retry после уже выполненного review; поздний scoped save; отсутствие частичных изменений.

Native SQLite: новый тест сохраняет карточку с `topicId:null`, citations, createdBy, due/reps, закрывает и повторно открывает временную БД. Некорректная запись в batch откатывает всю транзакцию; пользовательская БД не открывается.

E2E: 1 запрос → 2 черновика → выбрать/изменить 1 → сохранить 1 → reload → цитата → FSRS review; ошибка записи и retry без регенерации; быстрый повтор нажатия; optional topic только своего направления; invalid schema/чужой ID; длинная/пустая страница и отсутствие направления; закрытие pending generation; вход из предпросмотра и исторической цитаты; stale citation. Проверяются клавиатура, тёмная тема и светлая 1000×700 без горизонтального переполнения. Browser-ответы модели подменены; реальные запросы ИИ в этих тестах не выполнялись.

Ручная приёмка: выбрать с. 7 PDF → «Закрепить» → создать две карточки → исправить одну → вторую снять → сохранить → перезапустить приложение → повторение → открыть цитату с с. 7 → оценить ответ. Проверить, что старые карточки сохранили интервалы и лишних reviews до оценки не появилось.

Установщик: `desktop/releases/ConceptLoom_0.3.5_x64-setup.exe`. Автоматическая установка поверх пользовательской версии не выполняется.

## Границы

Предпросмотр не подтверждает истинность AI-ответов: точность проверяет пользователь по фрагменту. Авторские правки сохраняют исходную ссылку и отметку AI-происхождения. Черновики существуют до закрытия окна/перезапуска, не являются новой коллекцией заметок. Новый запрос после закрытия может создать похожие вопросы; предупреждение помогает их заметить. Полный quiz, генерация целой колоды и автоматические карточки по ошибкам не входят в P4.
